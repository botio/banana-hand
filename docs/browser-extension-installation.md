# 瀏覽器插件完整安裝教學

這份教學以**一般使用者**為主，一步一步說明如何下載、安裝、確認連線與更新 Banana Hand 的瀏覽器插件。不需要安裝任何程式語言、編輯器或開發工具；大部分動作都只要下載檔案、在瀏覽器頁面裡點幾個按鈕。

出現問題時，先看本文[順序確認清單](#before-start)與[常見問題](#troubleshooting)，再依[回報注意事項](#reporting)提供完整資訊，不要反覆重裝或停用安全功能。

## 安裝前先確認

插件不能單獨使用，它必須與 **Banana Hand 桌面 App** 配合。先把下列事項準備好：

1. **桌面 App 已安裝且正在執行。** 尚未安裝時，先看 [App 安裝教學](../README.md#desktop-install)。後續啟動沒有固定先後順序；首次安裝先開 App，較容易確認狀態。
2. **使用桌面版 Google Chrome 或 Mozilla Firefox。** 本教學以這兩種瀏覽器為準，不適用於手機版；Edge、Brave、Opera 等其他瀏覽器未納入這裡的安裝與驗證範圍。
3. **兩個已開啟、可辨識的一般網頁分頁。** 不要拿 `chrome://`、`about:` 設定頁或擴充功能管理頁當第一個測試目標。
4. **準備固定存放位置**：Chrome 需保留解壓縮後的資料夾；Firefox 直接安裝下載的 `.xpi`，不需解壓縮。
5. 確認下載的 App 與插件**來自同一個版本的發布頁**，且版本相同。

目前以 **0.1.17** 為例；新版請以該版本發布頁的檔案為準。Firefox 插件要求 **Firefox 140 或更新版本**。請在瀏覽器的「關於」頁查看版本，必要時先更新瀏覽器。

<a id="downloads"></a>

## 選擇正確的插件檔案

到 **[Banana Hand Releases](https://github.com/botio/banana-hand/releases)**，展開該版本的 **Assets**。一般使用者應選擇下列兩種：

| 你的瀏覽器 | 要下載的檔案 | 這份檔案會變成 |
| --- | --- | --- |
| Google Chrome | `banana-hand-chromium-<版本>.zip` | 解壓縮後，在 Chrome「載入未封裝項目」 |
| Mozilla Firefox | `banana-hand-firefox-<版本>-signed.xpi` | 在 Firefox「從檔案安裝附加元件」直接安裝 |

**不要選的檔案：**

- `banana-hand-chrome-webstore-<版本>.zip`：這是開發者上傳 **Chrome Web Store** 用的提交包，不是給一般使用者安裝的檔案。解壓縮後載入它不一定會在一般電腦運作。
- `banana-hand-firefox-temporary-<版本>.zip`：這是暫時除錯版，**Firefox 重新啟動後會失效，需要重新載入**。正式使用請選 `-signed.xpi`。
- `Source code (zip)`、`Source code (tar.gz)`：原始碼，不是安裝程式。

<a id="chrome"></a>

## Google Chrome 插件（解壓縮載入）

目前提供的是本機載入版，不是 Chrome Web Store 安裝連結。請在擴充功能管理頁開啟「開發人員模式」，再載入下載的插件資料夾；不需要安裝開發工具，也不要改動系統或瀏覽器安全政策。

### 第 1 步：解壓縮到一個固定的資料夾

下載 `banana-hand-chromium-<版本>.zip` 後，把它**解壓縮到一個你不會不小心刪掉的資料夾**（例如「文件 → BananaHand」或桌面上的專屬資料夾）。

解壓後，會看到一個名為 `banana-hand-chromium-<版本>` 的資料夾，裡面至少有：

```
banana-hand-chromium-0.1.17/
├── manifest.json      ← 「載入未封裝項目」時要選的檔案所在位置
├── background.js
└── icons/
    ├── icon-16.png
    ├── icon-32.png
    ├── icon-48.png
    └── icon-128.png
```

**要選的是資料夾，不是 `manifest.json` 檔案本身。** 選中的資料夾裡應直接看到 `manifest.json`、`background.js` 和 `icons/`，不要把它們拆開。

Windows 的「全部解壓縮」有時會在 ZIP 原有資料夾之外，再加一層同名資料夾。如果看到兩層 `banana-hand-chromium-0.1.17`，繼續打開，直到看得到上述檔案，再選擇這一層。

建議首次安裝就把這一層改成固定名稱，例如「文件 → Banana Hand → chrome-extension」，日後在原位置更新內容。資料夾名稱可以不同；插件版本以 Chrome 管理頁顯示的版本為準。

### 第 2 步：開啟擴充功能管理頁

在 Chrome 網址列輸入：

```
chrome://extensions
```

按 Enter。也可以按畫面右上角的拼圖圖示，選擇「管理擴充功能／Manage extensions」。

### 第 3 步：開啟「開發人員模式」

在擴充功能頁右上角，把「**開發人員模式／Developer mode**」的開關切到開啟。

沒看到這個開關時，先確認你是在 `chrome://extensions`，而不是普通網頁或 Chrome 商店。若開關不存在、無法開啟，或畫面顯示「由貴機構管理／Managed by your organization」，代表這台機器受政策限制，請找系統管理員，**不要嘗試繞過或修改瀏覽器企業政策**。

### 第 4 步：載入未封裝項目

1. 按畫面左上方的「**載入未封裝項目／Load unpacked**」。
2. 在選擇資料夾的對話框中，選到 **`banana-hand-chromium-0.1.17`** 那一層（裡面直接有 `manifest.json`）。
3. 按「選取資料夾／Select Folder」。

選擇**錯誤資料夾**時（例如選到只包含 `banana-hand-chromium-0.1.17` 的上一層、或選到 `icons`），Chrome 會提示找不到 `manifest.json` 或載入失敗。此時回到第 4 步改選正確那一層即可，不需要重新下載。

### 第 5 步：確認已啟用並顯示版本

載入成功後，清單會出現 **Banana Hand Browser Bridge**。確認開關已開啟；開發人員模式下可查看版本，也可進入「詳細資料／Details」核對。版本應與下載檔案相符。

不需要釘選工具列圖示，也不需要按圖示配對。插件沒有另外一個發送視窗，下一步是回到桌面 App 確認分頁清單。

**必須保留解壓縮資料夾與該層 `manifest.json` 的相對結構。** 之後每次開啟 Chrome，它都要從這個資料夾載入插件。若刪除或移動這個資料夾，插件會失效；移動後需重新「載入未封裝項目」指向新位置。

不需要一直停留在擴充功能管理頁。若瀏覽器之後顯示停用或安全提醒，先閱讀原因、確認項目是你從本專案安裝的插件；不要忽略惡意程式警告，也不要繞過組織政策。

<a id="firefox"></a>

## Firefox 插件（已簽署 XPI）

Firefox 版本使用已經由 Mozilla Add-ons(AMO) 簽署的 `.xpi`，因此**不需要**開啟任何開發者模式，也不需要解壓縮。裝好後 Firefox 重新啟動仍會保留。

### 第 1 步：下載 `.xpi` 檔案

下載 `banana-hand-firefox-<版本>-signed.xpi`。**不要更名、不要解壓縮。**

### 第 2 步：開啟附加元件管理頁

在 Firefox 網址列輸入：

```
about:addons
```

按 Enter，進入「附加元件管理員」。

### 第 3 步：從檔案安裝

1. 在附加元件管理員頁面上方或側邊，點**齒輪／設定**選單。
2. 選擇「**從檔案安裝附加元件…／Install Add-on From File…**」。
3. 在檔案選擇器中，選到剛下載的 `banana-hand-firefox-0.1.17-signed.xpi`，按開啟。
4. Firefox 會詢問是否安裝，並顯示所需權限。請閱讀後按「新增／Add」。

權限提示的文字會隨瀏覽器版本和語言不同。這個插件需要辨識分頁、切換目標，並與本機 App 通訊；相關用途見下方[權限與隱私](#privacy)。請先閱讀，只有同意時才安裝。

> 若「從檔案安裝附加元件」選項是灰色或無法使用，通常是瀏覽器受管理政策限制；請洽系統管理員，不要嘗試用開發者模式的「暫時載入」來繞過正式安裝需求。開發用「暫時載入」只能用於除錯，且 Firefox 重啟後會失效。

### 第 4 步：確認已安裝

安裝完成後，在「擴充套件／Extensions」清單找到 **Banana Hand Browser Bridge**，確認已啟用。點進項目詳細資訊，查看版本是否與下載檔案相符。Firefox 重新啟動後，已簽署安裝的插件仍應保留；沒有工具列彈出視窗需要配對。

### 版本與相容性

- 此版本的 Firefox 插件要求 **Firefox 140 或更新版本**（見 `strict_min_version`）。
- 「`-signed.xpi`」的「已簽署」表示可被標準 Firefox 正式安裝；**不代表已上架、自動更新，或在 Add-ons 搜尋目錄能找到。**
- 更新時要用新的 `.xpi` **覆蓋安裝同一個擴充套件**，不需要先解除安裝。

## 確認真的連線成功

完成插件安裝後，回到**仍在執行的 Banana Hand 桌面 App**。

1. 在已安裝插件的瀏覽器設定檔中，開啟兩個一般網頁。
2. 等待 App 上方狀態列出現類似 **「已連線 … 個可選 Browser Tab」**。
3. 展開「目標 01」或「目標 02」，確認看得到你開啟的網頁標題。

**成功標準：App 裡看得到你的分頁。**

單獨看到下列訊息，**不是**連線成功：

- 「native host 已自動登錄」：App 已準備好連線設定，但插件還沒連上或分頁快照尚未送達。
- 「native host self-check: ok」：App 內建的連線助手自我檢查通過，仍要確認分頁清單。
- 瀏覽器管理頁顯示插件已啟用：只是裝得好，不代表已連上 App。

Chrome 的「個人」「工作」是不同設定檔；插件裝在哪個設定檔，就先在那個設定檔測試。Firefox 不同設定檔也需各自安裝。不要因為同一台電腦有裝過插件，就認為所有瀏覽器視窗都已設定完成。

無痕／私人瀏覽另有插件權限限制，訪客模式也可能不同。首次測試先用一般視窗，不要為了排錯擴大私人瀏覽的權限。

App 與瀏覽器沒有固定先後順序；插件會自動重試。初次安裝若尚未出現分頁，可先等約一分鐘。仍無結果，查看[連線排錯](#troubleshooting)；不要改 `chrome://flags` 或 `about:config` 當成通用修法。

<a id="updates"></a>

## 更新 App 與插件

更新採手動方式：**先下載新版 App 明確更新，再更新插件的對應版本**。不要等待 App 自行下載更新，也不要以「解除安裝並清除回到出廠值」當成更新流程。

### 更新 Chrome 插件

**建議沿用目前已載入的資料夾，更新裡面的檔案：**

1. 下載新版 `banana-hand-chromium-<新版本>.zip`，先解壓到暫存位置，找出內含 `manifest.json` 的那一層。
2. 完全退出桌面 App，在 `chrome://extensions` 暫時關閉 Banana Hand 插件的開關。
3. 找到 Chrome **原本載入的資料夾**。若不確定位置，可在插件詳細資料中查看載入來源；確認前不要刪除任何資料夾。
4. 將舊插件資料夾複製一份作為備份，只更新原資料夾中的插件檔案。把新版的 `manifest.json`、`background.js`、`icons/` 等內容放進原位置，取代舊插件內容；**不要把新版整個資料夾再塞進舊資料夾，變成多一層**。
5. 回到 `chrome://extensions`，啟用插件，按該項目的「重新載入／Reload」（循環箭頭）。
6. 核對 Chrome 顯示的插件版本已變成新版。
7. 開啟更新後的 App，等分頁清單出現，再重新選取目標。

**只把新版解壓到另一個位置，再按舊項目的「重新載入」，不會更新插件。** Reload 讀取的是原本那個資料夾，不會自動尋找下載目錄中的新版本。

如果確實要換位置，需使用「載入未封裝項目」選取新資料夾，並核對版本及項目狀態。不確定目前讀取哪份檔案時先停下來確認；不要同時維持多份來源不明的 Banana Hand 插件。

### 更新 Firefox 插件

1. 下載新版本的 `banana-hand-firefox-<新版本>-signed.xpi`。
2. 在 `about:addons` 選「從檔案安裝附加元件」，安裝新版 `.xpi`，並閱讀 Firefox 顯示的更新或權限提示。發布版使用固定附加元件 ID，正常情況會更新原項目；不需先解除安裝或清除插件資料。
3. 保留插件啟用狀態，重新開啟 App 並確認分頁清單。

### 更新桌面 App

1. 完全退出舊版 Banana Hand。
2. Windows：執行新版 `.exe` 安裝程式。macOS：從新版 DMG 把 App 拖入「應用程式」覆蓋。Linux：依新版本安裝 `.deb` 或替換 AppImage。
3. 重新開啟 App。
4. macOS 更新後若系統再次要求「輔助使用」權限，請在「系統設定 → 隱私權與安全性 → 輔助使用」重新允許目前版本並重開 App。

一般更新不需要清除快捷鍵資料。重新開啟 App 後，目標分頁需重新選取，但快捷鍵庫會保留。若有重要快捷鍵，更新前可先記下名稱與組合，以便核對。

<a id="removal"></a>

## 停用或移除

「停用插件」「移除插件」「移除桌面 App」與「清除快捷鍵資料」是**四件不同的事**。

| 動作 | 在哪裡做 | 目的 |
| --- | --- | --- |
| 停用插件 | 瀏覽器擴充功能／附加元件管理頁，把開關關閉 | 暫停，之後可再啟用 |
| 移除插件 | 瀏覽器管理頁選「移除」 | 移除插件及其瀏覽器本機儲存資料 |
| 移除桌面 App | 作業系統正常的解除安裝／刪除 App | 停止桌面程式 |
| 清除快捷鍵 | 在 App 快捷鍵庫中，逐項按右側「×」 | 刪除不再需要的快捷鍵；與移除插件無關 |

**一般移除流程（不會動到你的網頁資料）：**

1. 先退出桌面 App。
2. 在瀏覽器管理頁移除 Banana Hand Browser Bridge。
3. 用作業系統正常方式移除桌面 App。

**Chrome**：先到 `chrome://extensions` 按 Banana Hand 的「移除／Remove」，確認項目已移除，之後才刪除專屬的插件資料夾。只刪除插件資料夾，不要刪除瀏覽器設定檔、整個「文件」或「下載」資料夾。

**Firefox**：到 `about:addons`，在 Banana Hand 項目的選單中選「移除／Remove」並確認。不需刪除 Firefox 設定檔。

若只是暫時不用，關閉插件開關即可，日後再啟用。移除插件不會替你刪除 App 儲存的快捷鍵；不要刪除整個瀏覽器資料目錄作為解除安裝方法。

<a id="troubleshooting"></a>

## 常見問題與排錯

依「安裝」與「連線」兩類，按步驟檢查。**每次只改一項，改完重測，不要一次改多個設定。**

### 安裝／載入問題

**Chrome 下載的檔案解壓後，找不到 `manifest.json` 資料夾要選哪層？**
解壓後找 `banana-hand-chromium-<版本>` 資料夾，這一層內部直接有 `manifest.json`、`background.js`、`icons/`。`icons` 只是一層圖示，不要選它；也不要只選 zip 解壓出來後、包含多個資料夾的那一層。

**Chrome 顯示「找不到 manifest.json」或「載入失敗（Load extension error）」？**
先核對下載檔名、確認 ZIP 已完整解壓，再選擇直接包含 `manifest.json` 的資料夾。若訊息指出 JSON 無效、檔案無法讀取或缺少必要欄位，保留完整錯誤，從同一發布頁重新下載並解壓到乾淨位置；不要自行修改 `manifest.json` 來掩蓋錯誤。這類訊息不能單靠文字就判定是某一種包裝下載錯誤。

**Firefox「從檔案安裝」選項是灰色、無法使用？**
先確認是在 `about:addons` 的齒輪選單，不是瀏覽器一般的「開啟檔案」。若正確選項仍受限，檢查是否由組織管理，必要時向管理員確認。不要改 `about:config` 的簽章強制設定。

**Chrome 開啟「開發人員模式」被停用或顯示受組織管理？**
表示這台裝置受企業政策控管。請向管理員確認，不要停用安全功能或嘗試繞過。

**Firefox 顯示「無法安裝」「未經驗證」或「檔案似乎已損毀」？**
確認是桌面 Firefox 140 以上、檔名以 `-signed.xpi` 結尾，而且沒有解壓或改寫內容。重新從 Release 下載；若仍失敗，保留完整提示、Firefox 版本與下載檔名回報。不要改裝未簽署版或關閉簽章檢查。

### 連線問題

**App 顯示「尚無 native host 連線」？**
1. 確認桌面 App 正在執行。
2. 到瀏覽器管理頁確認插件已啟用（Chrome）或附加元件已啟用（Firefox）。
3. 等約一分鐘讓自動重試完成。
4. 若仍未連上，Chrome 在 `chrome://extensions` 對 Banana Hand 按一次「重新載入」；Firefox 在 `about:addons` 把 Banana Hand 停用後再啟用，或正常重新啟動 Firefox。一般使用者不需進入 `about:debugging`。
5. 若 App 有「最近一次 extension 回報」，把它一併記下。

**App 顯示「native host self-check：failed…」？**
代表 App 的本機連線助手自我檢查失敗，可能涉及檔案缺失、啟動、連線或協定回覆；不能只憑 `failed` 判定是哪一項。記下後面的完整錯誤，確認 App 已完整安裝、沒有只複製主程式。macOS 若有明確的隔離阻擋，再參考 [App 安裝說明](../README.md#desktop-install)；輔助使用權限是輸入控制權限，不是所有連線失敗的通用修法。

**App 顯示「已連線但尚未收到 Browser Tab 快照」？**
代表目前尚未收到可供顯示的分頁資訊。先開啟一般網頁，等待更新；仍無清單時，依上一項方法重新載入 Chrome 插件，或停用再啟用 Firefox 插件。不要只憑這句話認定插件後台休眠。

**App 顯示「協定版本不符」？**
表示通訊協定主版本不相容，不代表任何 App／插件版本號不同都一定不相容。最容易排除混用的方法，是從同一個 Release 更新 App 與插件，再重新啟動 App、重新載入插件。

**看不到我的分頁，但插件已啟用？**
1. 確認頁面開在安裝插件的同一個瀏覽器設定檔與一般視窗（不是無痕）。
2. 初次測試選用一般網頁；某些瀏覽器內部頁面即使出現在清單裡，也不適合作為網站快捷鍵測試。
3. 等一段時間讓快照送達，避免剛開啟分頁就立刻回報。
4. 若網頁標題相似，先關閉不需要的分頁、依視窗與標題核對，再重新選取；不要憑選項位置猜目標。

**按插件圖示沒反應？**
這個插件的**介面在桌面 App，不在工具列彈出視窗**。請以 App 的分頁清單判斷是否連線成功，圖示本身沒有可見彈出內容是正常的。

### 發送／結果問題

**「目標視窗沒有成為前景（目前前景：banana-hand.exe）」**
- 先確認 App 已是 **0.1.17 或更新版本**，並重新啟動更新後的程式。
- 確認 Chrome 視窗可正常操作、沒有阻擋中的對話框，發送期間沒有手動切到其他程式。
- 仍頻繁出現時，把完整訊息與版本回報；不要為送出按鍵停用前景檢查，也不要把重送當成一般排錯步驟。

**「已嘗試發送」但網頁沒反應**
- 先到網頁手動按一次同樣組合，確認網站本身認得這組按鍵，且焦點不在網址列或某個輸入框。
- 檢查快捷鍵是否被瀏覽器本身攔截（例如某些 `Ctrl` 組合）。
- 若手動可用、透過 App 不可用，保留組合與兩個目標的結果回報；不要用連續重送測試可能重複執行的動作。

**「目標前景驗證逾時」**
表示等待目標準備回覆時逾時。先核對版本、分頁連線與完整錯誤；不能直接斷定是系統忙碌。若第一個目標可能已執行，先檢查兩邊的結果，不要直接重送整組。

**發送按鈕是灰色，或顯示「冷卻 … 秒」？**
確認已選一個快捷鍵、兩個不同且仍連線的目標。若在冷卻，等待 60 秒全域倒數結束；更換快捷鍵或分頁不會跳過冷卻，不需重裝。

**結果出現 `partial`／部分目標已嘗試？**
第一個目標可能已經執行，第二個才失敗。先分別查看網頁狀態，再決定後續處理；不要直接重送兩個，尤其不要用付款、刪除或送出表單等動作反覆測試。

### 其他

**Linux（Wayland）顯示權限／portal 拒絕？**
目前 Wayland 發送尚未實作，不是授予一個權限就能修好；先改用可用的 X11 工作階段（見 README）。

**我要輸入 extension ID、改登錄檔或另外裝 host 嗎？**
使用這份教學的標準安裝流程不需要。一般使用者應先確認 App 與插件檔案正確；手動 host manifest 與 extension ID 設定屬於[開發者文件](development.md#native-host)，不是初次安裝的必要步驟。

**App 重啟後分頁要重選？**
正常。目標選取是 session-only，每次重開 App 都要重新挑選；快捷鍵庫則會保留。

> 若某個建議要求你「關閉瀏覽器簽名強制」「修改 `about:config` 以允許未簽署」「關閉 SmartScreen/Gatekeeper」或「反覆重送 partial」，這不是本專案建議的操作；請不要為了排錯而降低系統安全。

## 回報問題

在 [GitHub Issues](https://github.com/botio/banana-hand/issues) 回報時，提供：

1. 作業系統與架構（例如 Windows 11 x64、macOS Sonoma Apple Silicon、Ubuntu 24.04 x64）。
2. App 版本與瀏覽器名稱／版本、插件版本。
3. 問題階段：載入、連線、選取、發送。
4. App 完整的錯誤原文，或遮蔽過的截圖。
5. 使用的快捷鍵，以及兩個目標各自實際觀察到的結果；是否同一設定檔、是否一般視窗。

**GitHub Issues 是公開的。** 請遮蔽私人分頁標題、含識別碼的完整網址、帳號、密碼與權杖，不要貼整份連線設定檔。

<a id="privacy"></a>

## 權限與隱私

| 權限／提示涉及的能力 | 在 Banana Hand 的用途 |
| --- | --- |
| 存取分頁資訊 | 取得標題、網址、視窗與分頁識別資訊，供 App 列出及選取目標 |
| 與本機程式通訊 | 把分頁資訊交給同一台電腦上的桌面 App，並接收目標準備要求 |
| 本機儲存 | 保存隨機產生的設定檔識別碼，區分不同瀏覽器設定檔 |
| 背景排程 | 在連線失敗或背景重新啟動後安排重連 |

Firefox 也可能提示瀏覽活動相關資料權限；分頁標題與網址本身就可能包含個人資訊。插件會處理已開啟分頁的資訊，不限於最後選中的兩個，但不讀取網頁正文、表單、密碼庫或瀏覽歷史資料庫。這些分頁資料不會由插件自動傳送到開發者伺服器。

請閱讀 [隱私權政策](../PRIVACY.md)，只有在接受這些用途時才安裝；不用時可停用或移除。

官方參考：[Chrome 載入未封裝擴充功能](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked)。官方範例的彈出視窗不是 Banana Hand 的介面；本插件仍由桌面 App 操作。
