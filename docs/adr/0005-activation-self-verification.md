# 激活步驟自我驗證並回報視窗標題

v0.1.9 在 `open -a` 之後增加有界前景驗證與一次重試，並加入視窗標題。當時將「目前前景：G」歸因於其他 Space，缺乏證據；使用者後續確認 v0.1.9 畫面確實跳到目標分頁，此推論不能作為根因。

v0.1.10 更正：真正可重現的問題是 `CFStringGetCString` 的 Boolean 成功值被當成位元組長度，導致前景名稱只剩一個位元組。修正型別與 UTF-8 長度使用；不新增啟用重試，也移除把驗證失敗指向 Space 的錯誤提示。加入真正 CoreFoundation 的 macOS 回歸測試，驗證完整 browser 名稱與 Unicode 標題。

## Consequences

既有 `activate` 輪詢在閘門之前執行；若它拒絕，後續閘門不會執行，不能把兩者時間直接相加。`kCGWindowName` 可能因系統權限或視窗狀態缺失，不保證可取得；標題缺失不代表位於其他 Space。macOS 真實快捷鍵送達仍須實機驗證，編譯通過不是送達證明。
